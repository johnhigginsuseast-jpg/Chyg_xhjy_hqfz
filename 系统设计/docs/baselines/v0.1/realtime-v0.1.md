## 1. 用户场景与范围

面向本机研究用户，持续观察新行情的模型方向及可复核结果。建议首版只做 HTTP 完整分钟 K 线、现有 1min-h1-logistic 冻结模型、SQLite 账本、控制台统计。Windows，本地已有 Python 环境。

排除自动交易、账户操作、付费调用、模型重训、改阈值、多品种、多周期并发、网页/云发布、WS 报价展示和二进制缓存适配器。备选路线留在调查文档，不以实现选项扩张本版。

本版所有运行输出放本工作区；原始 CSV、客户端和现有模型保持原位。来源绑定所需的原预测入口最小扩展须在开发时单列变更和回归，不能静默跳过既有来源验证。

## 2. 展示与操作

首版无图形前端，控制台按固定顺序显示：源连接/完整性/延迟状态→品种/模型/部署→锚点与发布时间→UP/DOWN、p_up/p_down、置信度、wait/规则跳过→今日及部署以来统计→最近预测/结果。标签同时显示研究用途及目标是否已经开盘。

启动加载显示 WARMUP；无结果显示“暂无可计分样本”；断线/陈旧/身份异常显示原因与最后成功时间；不得沿用旧方向伪装为当前预测。Ctrl+C 安全停止。持久化失败不展示正式信号。信息不只靠颜色区分；无额外网页/权限页。

## 3. 功能要求

| 编号 | 必需行为 | 边界/异常 |
|---|---|---|
| FR-RT-001 | 建立训练源、实时源、品种代码/名称、周期、时区、价格/成交量单位和模型摘要的可审查绑定 | 对账或身份未确认，禁止正式发预测；新源不能冒用旧 source_identity |
| FR-RT-002 | 仅调用核实的行情 HTTP，映射 1 分钟到接口 period=0，保留必要响应及接收时间 | 失败超时退避；不读取凭证、不修改客户端、不自动换源 |
| FR-RT-003 | 校验字段/OHLCV/时间/重复/乱序/完整根/开盘事件与来源修订 | 形成中根和无法确认完整性的根不进特征；异常事件留痕 |
| FR-RT-004 | 复用当前规范化、64 有效根热身门槛及完整历史依赖、三连跳两根、39 特征、冻结概率和阈值 | 暖机不足不预测；h 按未来有效根；wait 保留方向；平手沿用 UP |
| FR-RT-005 | 每锚点至多一条正式预测；分别记录锚点、接收、计算、真实持久化发布时刻及输入/模型版本 | 在目标结果已可知或超过固定延迟后发布的记录不进入正式前向命中率 |
| FR-RT-006 | SQLite 持久化预测、行情及结算；按原规则判断未来目标，自动产生 PENDING/HIT/MISS/FLAT/UNSCORABLE | 预测不改写；结果修订留版本；规则跳过存事件，不伪造概率 |
| FR-RT-007 | 主统计全量有效二分类预测；另列信号子集、覆盖率、状态计数、样本量与 95% Wilson 区间 | 不删除低置信度或错误样本；0 分母不显示 0%/100%；历史和实时/不同源与部署不混算 |
| FR-RT-008 | 重启/重连可恢复状态，补回数据仅用于重建和结算，缺数与休市分开 | 不补发过去预测；不能证明目标序列则暂停结算，按已确认期限标记无法评分 |
| FR-RT-009 | 控制台提供本节所列信息和空/加载/失败/成功状态，可停止 | 保留最后状态但明确过期；从账本重算后结果一致 |

## 4. 数据保障和非功能要求

行情按源/品种/周期/原时间/修订存储；时间同时保留原标签、经验证的 UTC 和接收时间。部署冻结模型、来源绑定、规则、采集/最终性/延迟策略和前向启用时刻。日志只留行情及运行诊断，不收集账户、cookie、token、私钥。数据库写失败停止正式发布，单事务保证记录一致；有一致性备份与恢复验证。

| 编号 | 必需要求 | 建议测量条件/门槛（本次待确认） |
|---|---|---|
| NFR-RT-001 | 固定性能及迟到边界 | 单模型/1 分钟、本机 CPU 最多 4 线程；轮询 3 秒；连续至少 60 个完整可预测锚点，锚点至持久化发布 p95≤20 秒；超过 20 秒的个别输出必须记 LATE，不得悄悄计分 |
| NFR-RT-002 | 故障不伪造数据/预测/命中率，可恢复且无重复 | 回放覆盖断网、重复、乱序、缺根、写失败、进程退出；同一输入和模型重复运行结果一致；SQLite 一致性备份可恢复 |
| NFR-RT-003 | 原材料、可信模型加载及本地数据访问边界保持有效 | 原客户端无写入；模型哈希/路径检查保留；不安装依赖、不读取凭证、不连接交易接口 |
| NFR-RT-004 | 指标有真实、可重复的证据 | 每个汇总能追到预测及发布/目标证据；样本量不足不宣称效果，既有历史 55.68% 不冒充实时表现 |

功能效果：本版验收的是数据接入、前向时序和正确统计；不承诺命中率高于 50%、70% 或其他值。建议展示至少 500 个可计分前向样本的效果报告，未达此规模时显示样本不足；达到规模也不自动代表信号有效。

## 5. 操作流程

用户启动本地程序→验证固定部署与来源绑定→历史暖机→只对启用后新锚点发预测→显示持久化回执→目标完成后显示结果和统计。断线则显示状态并暂停，恢复后重建；用户停止后重启不重复发布。备份恢复另按独立检查验证，不用历史回放替代真实采集。

## 6. 待决与确认

| 项目 | 推荐 | 确认前限制 |
|---|---|---|
| 目标品种 | 沿用当前历史说明的“印江花果红茶二期”，从真实行情元数据核实代码；不默认套用 531 | 未核实绑定不得正式预测 |

| 发布时间含义 | 上一完整根验证后预测未来有效收盘，明确目标可能已开盘 | 若要求目标开盘前发布，需重新定义时序与验收 |
| 实时最终性、时区与单位 | 先取样验证和重叠对账，保留真实差异 | 收盘机制未建立或对账不通过，不接模型 |
| 建议数值 | 3 秒轮询；20 秒发布边界；60 个锚点测 p95；跨两交易时段至少 100 个重叠根对账；至少 500 计分样本作效果报告 | 均为本次待确认设计值，不是已达到指标 |
| 缺数到期 | 缺数期间暂停；补回和完整性无法确认的预测，在两个后续已验证交易日完成后转 UNSCORABLE | 真实交易日历未核实时不能套用自然日超时或把缺数当休市 |
