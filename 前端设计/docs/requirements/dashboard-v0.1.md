## 1. 目的、范围与技术选择

为本机研究用户提供一个中文只读仪表盘，观察系统与数据状态、1分钟行情、下一根有效K线的预测和已有实际结算。当前HTTP跨源前向研究、单品种531、现有1分钟h=1模型和计分不变；网页不重新运行模型、采集行情或结算。

推荐原生HTML/CSS/JavaScript + SVG图表，配套Python标准库HTTP服务。服务与静态资源均在前端目录，复用已核实Python 3.12.14，同源、仅绑定127.0.0.1:8765；端口占用清楚报错，不关闭其他进程。无需Node构建、数据库迁移、外部CDN、付费服务或新框架。未来启动脚本只启动网页服务，不导入或启动采集器。

当前没有可复用的网页API。推荐在新目录实现固定路径SQLite只读适配，**现有系统文件零修改**。只做静态演示不能满足最终真实监控；给原采集器添加HTTP接口/PID心跳会影响冻结系统，首版不采用。详见第4节。

排除交易下单、账户/登录、资金管理、模型训练/选模/改阈值、多品种切换、云发布、远程局域网访问、供应商行情直连和任意文件浏览。已确认数据源差异和未校准概率必须可见，不能暗示模型有效或盈利保证。

## 2. 页面结构与视觉

单页，无额外导航系统。桌面结构：

```text
品种 / 1分钟 h=1       HTTP跨源前向研究 · 未验证稳定效果
系统状态：进程 | 页面连接 | 行情连接/处理 | 常规休市/交易状态
模型 / 来源 / 部署 / 业务数据截止 / 最近成功获取 / 页面刷新
┌ 1分钟K线 + 成交量（约2/3宽） ┐ ┌ 当前预测（约1/3宽） ┐
└ 源时间、完整性、原始单位、图例 ┘ └ 方向、概率、锚点、回执 ┘
已计分 / 命中 / 未命中 / 平盘 / 待结算 / 无法计分
累计命中率 / 今日命中率 / n与区间 / 样本不足提示
累计命中率趋势（不足则说明）
预测记录：日期、状态筛选；倒序表格；翻页；单条详情
```

默认深色，中性背景与清晰分隔，中文系统字体；红色↑上涨、绿色↓下跌、灰色—平盘，始终同时用文字/图标及图例。长时间查看不加入装饰动画、自动跳动数字或大面积光效。手机将区域依次堆叠；记录表可在自身区域横向滚动，页面本身不横向溢出。详情用侧栏/手机弹层，能键盘打开、Esc关闭、焦点返回原记录。

## 4. 最小只读接口方案（已随本版本确认）

### 4.1 文件与数据边界

新增文件仅在前端目录：`server.py`、`web/index.html`、`web/app.js`、`web/styles.css`、`启动监控网页.cmd`，以及测试、演示夹具和证据。本节是拟改动清单，现有系统没有拟修改文件。

服务仅打开固定的 `系统设计/runtime/http-research/forward.sqlite3`，使用SQLite URI mode=ro和query_only，只读事务；无文件不存在时创建数据库的分支。固定读取该目录的deployment.json和可信模型JSON元数据以绑定身份，不加载joblib、不导入模型/采集启动入口、不实例化会写入的Ledger构造函数。原系统独立运行；网页可在其停止时展示已有数据但必须说明未知/过期。

只读服务按现有Ledger.summary/发布/结算规则实现查询映射，不修改原分母或原库。存在重复映射发生漂移的风险，所以**同截面与原汇总逐字段对齐是必需验收门槛**；原实现仅在隔离测试副本中作为对照，不用生产库运行有写入的状态命令。不匹配或契约无法识别就返回错误，不继续显示可信统计。部署、source和mode不混合。

### 4.2 单一数据入口

拟提供 `GET /api/dashboard`，返回一个完整页面快照；静态页面与其同源，不另开行情代理或写接口。

可选查询仅有记录日期from/to（YYYY-MM-DD，起止日均含）、结算status（白名单）、分页before游标、limit（默认50/最大100）、bars（默认240/最大600）、所选prediction_id。游标只包含受校验的排序键，不接受路径、SQL、任意部署或任意文件参数。非法参数400，不属于当前部署的记录404；数据库不可读/忙、绑定错误等503并给安全错误码，不返回本地堆栈或敏感路径。

| 返回区域 | 关键字段/来源 | 处理要求 |
|---|---|---|
| snapshot | id、observed_at_ms、data_as_of_ms、last_completed_poll_id、timezone | 全页业务数据截止最后完成POLL，不能读到本轮未完成写入；诊断观察时刻单列 |
| identity | name、symbol、source、mode、model_version、deployment、research_only、domain_shift_acknowledged、units | 部署文件和库内payload校验一致；model_version取可信JSON及已有MODEL_INPUT |
| status | process=UNKNOWN及证据说明、来源code/detail、last_poll/last_success、last_stop_event | 近期POLL只表示近期账本活动。最近成功时刻取success=true的POLL.received_ms；STOPPED仅为最后停止记录，不单独证明当前进程已停 |
| market | latest_observed_bar、last_complete_ms、bars、raw_units | ts/raw_ts和版本received_ms分开；按截止选最新修订；非分钟隔离事件排除，完整性未知不伪装完成 |
| prediction | context、current_prediction或null、last_prediction或null | 服务按已有游标、回执、状态与结算作保守展示资格映射；不新预测、不新结算。目标尚未记录不猜测 |
| statistics | cumulative、today、today_date | 返回原口径所有状态/n/rate/Wilson/late/revisions及不足标记；浏览器仅格式化，不重新计分 |
| trend | [{as_of_ms,hit_rate,scored}] | 服务按历史时点已有证据计算；没有分母的点不伪造0%，不跨源/部署 |
| records/detail | 列表、分页信息、已选记录详情、规范化筛选条件 | 与全页相同业务截止；筛选不改变全局统计；数据修订可见 |

服务在一个只读事务内确定最新已完成POLL及业务截止，行情修订、发布回执、计算时刻和结算都按该截止裁剪；未回执记录保留原系统无法计分语义。完整历史图以已有BOOTSTRAP/CURSOR等证明为界，不能只比较墙上时间就把形成中根当完整。

诊断观察时刻允许列出业务截止之后已记录的停止事件，但它明确标“最后停止记录”，不混入业务汇总；没有完成POLL时，仍可返回身份/诊断，业务图表与统计显示“尚无完整快照”，不是假定0样本。多个区块一起替换为同一响应的snapshot.id；过时/乱序响应丢弃。详情点击也返回完整同截面响应，避免新统计搭配另一个时点的详情。

### 4.3 安全与模式

仅GET和必要HEAD；拒绝写方法，固定静态资源白名单，无目录列表、下载SQLite、任意文件读取、通用SQL或进程控制。仅允许本地Host和同源浏览器访问，不开放通配CORS；校验参数与长度，数据库内容按文本渲染以防脚本注入。

DEMO为显式独立启动模式，API和页面始终标DEMO/演示数据，数据来自前端目录夹具。真实服务不可用时保持错误，不能自动用演示响应装成LIVE。模式切换需明确重新进入/启动，缓存按模式/来源/部署隔离。服务和测试不向真实账本插入任何内容。
